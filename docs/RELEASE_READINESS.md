3. After deploy: `GET /api/health` → `database: ok`; sign in; edit one section; confirm `/services/software-development` = 200 and `/services/does-not-exist` = 404; check the hero on a real phone and laptop.
4. Rollback: redeploy the previous Vercel deployment (`50f58c0`) from the Vercel dashboard. The additive tables can stay in place.
5. Security follow-ups: re-save the database and backup secrets as Vercel *Sensitive* variables; remove `ADMIN_SETUP_TOKEN` once owner login and recovery are confirmed and a second Owner exists.
